# RTX Spark 端侧 AI 芯片简介

> 英伟达 2026 年 10 月 16 日开卖的 Windows 端侧 AI 芯片 **RTX Spark（N1X）**，用统一内存在笔记本上跑本地模型。量化图像和能装进内存的模型是它的强项；逐字生成受大约 300 GB/s 的内存带宽限制。价格取 2026 年 10 月 9–19 日的京东与评测口径，机型和国补之后会变。对照卡按当时常见的桌面 **RTX 5060 Ti 16 GB**（约 448 GB/s、功耗上限 180 W）来写。

- Windows Central、Notebookcheck 等独立评测（文中表格所引）

## 1. 定义

RTX Spark 把 Blackwell GPU 和 Arm CPU 做在一颗芯片上，预装 Windows 11 on Arm，用 CUDA 跑本地模型。台积电 3nm。CPU 与 GPU 之间用 NVLink-C2C，双向约 600 GB/s。支持第五代 Tensor Core、DLSS 5、光追、TensorRT、NVFP4。

**结论性定义：** 它是一颗功耗约 45–140 W 的 Windows 端侧超芯片。图形性能大约在移动版 RTX 4070 / 5060 这一档。1 PFLOP FP4 是含稀疏的宣传峰值，主要体现在预填充和低精度矩阵乘；逐 token 生成看的是内存带宽。

官方两档都叫 N1X。购买时要看核心数和内存，不能只看「RTX Spark」。

| | 满血（笔记本 / 台式机） | 残血（基本只上笔记本） |
| --- | --- | --- |
| CPU | 20 核 Grace（10×Cortex-X925 + 10×Cortex-A725，大核最高约 4.1 GHz） | 18 核（9+9，大核约 3.9 GHz） |
| GPU | Blackwell，6144 CUDA，48 SM | 5120 CUDA，40 SM |
| 内存 | 统一 LPDDR5X-9400，最高 128 GB，约 300 GB/s | 官方页写到 64 GB；国内首发多为 24 / 32 GB |
| 功耗 | 笔记本约 45–80 W；台式机规格表到 140 W | 约 45–80 W |
| AI 算力 | 最高约 1 PFLOP FP4（含稀疏） | 同架构，核心更少 |
| 系统 | Windows 11 on Arm，CUDA 原生 | 同左 |

更早的 DGX Spark（GB10）是同一类超芯片，面向 Linux 开发小主机，不是这款消费级 Windows 产品。

## 2. 适用边界

| 对照 | 本文所指 |
| --- | --- |
| 指令集与系统 | Armv9 CPU，预装 Windows 11 ARM64。x64 程序靠 Prism 模拟，内核驱动不能模拟 |
| 相对桌面独显 | 统一内存约 300 GB/s，笔记本整颗约 45–80 W，适合把更大模型装进本机；同尺寸模型的出字速度低于 180 W、448 GB/s 的桌面 5060 Ti |
| 内存容量 | 24 GB 到 128 GB 共用约 300 GB/s 带宽。容量决定能装下的模型，不决定每个字的读取速度 |
| 算力宣传值 | 1 PFLOP 描述含稀疏的 FP4 矩阵乘，主要体现在预填充；70B 稠密模型 Q4 的生成大约 4–6 token/s |

一句话：RTX Spark 用统一内存换可装入的模型规模，用低功耗换笔记本形态。出字速度仍由带宽决定。

## 3. 独立评测里的性能

Windows Central 测的是 128 GB / 6144 核的 Surface，Notebookcheck 测的是 64 GB 的华硕 ProArt P16。

| 方面 | 结果 |
| --- | --- |
| CPU | 多核接近 AMD 锐龙 AI Max+ 395、苹果 M4 Pro。单核明显落后苹果 M5 Pro / M5 Max 和高通骁龙 X2 Elite Extreme。Cinebench 2024 单核约 130 分、多核约 1726 分 |
| GPU / 游戏 | 3DMark Time Spy 约 12771。1440p 高画质能玩，吃紧的游戏靠 DLSS 和帧生成。视频导出略慢于同场景里的 RTX 5060 笔记本独显 |
| AI 图像 | Stable Diffusion 1.5 的 INT8 明显快于被测的 RTX 5060 / 5070 Ti / 5080 笔记本 |
| 小模型文本（Procyon） | Phi-3.5-mini 约 72 token/s，Mistral 7B 约 53，Llama 3.1 8B 约 49，Llama 2 13B 约 27。首 token 都在 1 秒以内 |

7B–32B 很顺。70B 稠密模型在 64 GB 以上能装进去，聊起来偏慢。带宽约 300 GB/s，和苹果 M5 Pro 接近，远低于桌面 RTX 5090 那类显卡。

## 4. 能部署的模型

英伟达按内存给的官方上限，以及更合适的用法：

| 统一内存 | 官方说法 | 实际更合适的用法 |
| --- | --- | --- |
| 24 GB | 约 12B | Qwen3 / Llama 8B–14B，Q4 很顺；32B 会很紧 |
| 32 GB | 约 25B | 14B 长上下文、Qwen3-30B-A3B 这类小 MoE、32B Q4 能跑但余量少 |
| 48 GB | 约 60B | 32B 舒服，可上 70B 的强量化 |
| 64 GB | 约 90B | 70B Q4（约 40 GB）能跑；生成大约 4–6 token/s，适合慢慢读 |
| 128 GB | 约 200B；产品页另写「120B + 100 万上下文」 | 这档才适合当本地大模型机 |

128 GB 上按好不好用划分：

| 用法 | 模型与速度 |
| --- | --- |
| 日常主力 | Qwen3-32B、Qwen2.5-Coder-32B、Gemma 27B、DeepSeek-R1 14B/32B。Q4 大约 10 token/s 上下。同级 DGX Spark（128 GB、273 GB/s）上，Qwen3-32B Q4 约 9.4 token/s，Gemma3-27B Q4 约 11 token/s |
| 优先的大模型 | MoE。OpenAI gpt-oss-20B（MXFP4）在 DGX Spark 上约 58–83 token/s；gpt-oss-120B 约 41–55 token/s。Windows Central 确认 128 GB 的 RTX Spark 能把 120B（Nemotron、GPT-OSS）整模放进 GPU |
| 能跑但偏慢 | Llama 3.1/3.3 70B、Qwen2.5-72B、DeepSeek-R1 70B，Q4 约 4.5–6 token/s。Llama 3.2 Vision 90B 约 3.5 token/s。Mistral Large 123B 约 2 token/s |
| 单机放不下或很勉强 | Qwen3-235B。DGX Spark 要两台用 ConnectX 互联，NVFP4 约 12 token/s。DeepSeek-V3 / R1 671B、Llama 405B 不在范围内 |

微调：DGX Spark 官方支持到约 70B 的 QLoRA。RTX Spark 软件栈同为 CUDA / TensorRT。64 GB 以上做 32B 及以下更现实，70B 微调要 128 GB。

买来主要跑大模型：24 GB / 32 GB 适合 14B–32B。70B 至少 64 GB。120B 的 MoE 或更长上下文直接上 128 GB。

粗算：每秒字数 ≈ 显存带宽 ÷ 模型在显存里的体积。70B 的 Q4 约 40 GB，300 ÷ 40 ≈ 7 字/秒，扣掉开销后往往是 4–6 字/秒。128 GB 的带宽仍是约 300 GB/s。

## 5. 和桌面 RTX 5060 Ti 16 GB 的差距

20 核那一档是满血 GPU：6144 个 CUDA 核心。32 GB 是 CPU 和 GPU 共用的 LPDDR5X。整颗芯片在笔记本上约 45–80 W，14 寸轻薄本更靠近下限。桌面 5060 Ti 是 4608 个 CUDA 核心、16 GB 独立 GDDR7、带宽 448 GB/s，显卡功耗上限 180 W。

| | RTX Spark 20 核 / 32 GB 笔记本 | 桌面 RTX 5060 Ti 16 GB |
| --- | --- | --- |
| 系统 | Windows 11 ARM64 | Windows 11 x64 |
| CUDA 核心 | 6144 | 4608 |
| 显存 | 32 GB 统一内存，GPU 实际可用大约 20 GB 出头 | 16 GB 独显，全部给 GPU |
| 显存带宽 | 约 300 GB/s | 448 GB/s，高约 50% |
| 显卡功耗 | 整颗 SoC 约 45–80 W | 显卡 180 W |
| FP32 峰值 | 满频大约 31 TFLOPS，轻薄本维持不住 | 常见加速频率下大约 24–25 TFLOPS，180 W 能稳住 |
| Time Spy 图形分 | 6144 核较厚机型实测约 12370 | 桌面 16 GB 卡大约 15200–15600 |

**游戏和普通图形：桌面卡大约快 25%–40%。** 已公布的 Spark 图形分来自 Surface、ProArt P16 这类功耗较高的机器，Time Spy 图形分比 5060 Ti 低大约四分之一。Steel Nomad 大约 3064 对桌面 5060 Ti 的 3500 左右，差约 15%–20%。14 寸机身持续游戏的差距还会再大。Spark 的 CUDA 核心数多出约三分之一，频率、功耗和带宽都更低。

**能放进 16 GB 的模型：桌面卡大约快 1.5 倍。** 7B–14B 的生成速度由带宽决定。448 GB/s 对 300 GB/s。180 W 对 80 W 也使预填充更快。现成的 x64 推理栈可以直接用。

**超过 16 GB 的模型：Spark 能装下，16 GB 独显要溢出。** 32 GB 统一内存的官方上限大约是 25B 参数。Qwen3-32B 的 Q4（约 18–20 GB）在 Spark 上可以整模放进内存；在 16 GB 的 5060 Ti 上会有一部分落到系统内存。70B、120B 两边都跑不好：32 GB 和 16 GB 都不够。

**CPU 跑分接近，x64 软件更顺。** Spark 20 核在 Geekbench 6 上单核约 3100、多核约 20000，和高端桌面 x64 同一档。Spark 上未适配的 x64 程序要走模拟，驱动也不能模拟。

32 GB 的 Spark 笔记本换不来比这张 5060 Ti 更强的游戏或小模型性能。它多出来的是续航、体积，以及大约到 30B 的模型。要在能跑的模型规模上超过这张卡，需要 64 GB 或 128 GB。

## 6. 带宽、容量和预填充

显存带宽决定模型放进显存之后每秒能读出多少数据。显存容量决定最大能放进多大的模型。容量够只说明装得下。

每生成一个字，都要把整个模型的权重从显存里读一遍。权重几乎不变，所以生成速度卡在读取，很少卡在算术峰值。

**每秒生成字数 ≈ 显存带宽 ÷ 模型在显存里的体积**

以 14B、Q4、约 9 GB 为例：

| 机器 | 计算 | 大约速度 |
| --- | --- | --- |
| 桌面 5060 Ti，448 GB/s | 448 ÷ 9 | 50 字/秒 |
| RTX Spark，300 GB/s | 300 ÷ 9 | 33 字/秒 |

448 ÷ 300 ≈ 1.5。核心数和 180 W 功耗对这一步影响小。它们主要影响预填充：把长文读懂、算出第一个字。这一步是大块矩阵运算。

容量和带宽由不同零件决定。5060 Ti 的 8 GB 版和 16 GB 版带宽都是 448 GB/s，16 GB 只是在 128-bit 接口上换了更大的颗粒。5060 Ti 是 128-bit GDDR7、等效 28 Gbps。RTX Spark 是 256-bit LPDDR5X，接口更宽，内存类型更慢，结果约 300 GB/s。

| | 容量 | 带宽 | 结果 |
| --- | --- | --- | --- |
| 5060 Ti 16 GB | 中等 | 448 GB/s | 14B 又快又够用，32B 装不下 |
| Spark 32 GB | 更大 | 300 GB/s | 32B 能装下，14B 比 5060 Ti 慢 |
| Spark 128 GB | 很大 | 仍约 300 GB/s | 120B 的 MoE 能装下，稠密 70B 约 5 字/秒 |

预填充是开口前的那一步：把整段提示和权重做矩阵运算，一次算完。同一批权重被反复用来乘很多字，显存只读少数几遍。谁的 Tensor Core 每秒乘加更多，第一个字就更早出现。

逐字生成时，下一个字依赖上一个字，每出一个字都要把权重再读一遍。速度改由带宽决定。

用 2000 字材料和一个 8B 模型看量级（同级硬件的实测量级）：

| | 预填充 | 接着往下写 |
| --- | --- | --- |
| 速度 | 大约每秒处理几千到一万字提示 | 大约每秒写出 30–50 字 |
| 2000 字提示 | 零点几秒出第一个字 | 之后每秒仍是几十个字 |
| 卡在哪 | 算力、功耗 | 显存带宽 |

提示很短时，预填充几乎感觉不到，差别主要在出字速度。

## 7. 系统架构和软件

CPU 是 Armv9（Cortex-X925 / A725）。日常软件分三条路：

| 软件类型 | 运行方式 |
| --- | --- |
| 已提供 ARM64 版本的程序 | 原生运行。新版浏览器、Office、Adobe 等 |
| 普通 x86 / x64 用户程序 | Windows 的 Prism 即时翻译。主流软件大多能开，没有原生版时更慢。个别依赖老驱动或内核组件的软件不能用 |
| 显卡驱动、CUDA、PyTorch | 必须是 Windows ARM64 版本。模拟器只翻译 CPU 指令。从 x64 机器拷来的 Ollama、llama.cpp、CUDA 安装包不能用 |

游戏大多是 x64 程序加模拟，GPU 仍走原生 DirectX / DLSS。反作弊已覆盖一批主流游戏，但不是全部。内核驱动必须是 ARM64。打印机、部分企业 VPN、银行 U 盾、部分杀毒和虚拟化软件，若只有 x64 驱动，就装不上或功能残缺。

办公：Edge、Chrome、微软 365、Teams 有 ARM64 原生版。WPS 已有 Windows on Arm 原生版（ARM64EC）。微信自 3.9.12.51、钉钉自 7.6.45 起可通过 Prism 运行，不是原生版。从 x64 电脑拷来的安装包、conda 环境、venv、`node_modules` 里的原生模块不能直接用。

开发：VS Code、Windows Terminal、Node、Go、Rust、JDK 有原生 ARM64。Python 3.15 起 Windows on Arm 默认是原生 ARM64。要用 GPU 跑 PyTorch，需 CUDA Toolkit 13.4.2 或更高，以及 RTX Spark 驱动。2026 年 10 月 15 日前后，CUDA 版 PyTorch 轮子覆盖 Python 3.11–3.14（含 3.14t），没有 3.15。PyPI 上的普通 `pip install torch` 当时没有 Windows ARM 轮子。应使用 Python 3.14，从英伟达的 Windows ARM 索引安装。

Windows x64、Windows ARM64、WSL 里的 Linux ARM64 是三套包。官方当时列出的缺口包括 cryptography、grpcio、PyArrow、tiktoken、OpenCV，往往要在本机从源码编译。英伟达称热门 Python 轮子大约 97% 已就绪，个别关键包仍要自己编。Docker 可用，容器架构是 Linux ARM64，现有 x64 镜像不能原样搬过去。

## 9. 怎么选

| 目的 | 当时更合适的机器 |
| --- | --- |
| 便携，并把 120B 级 MoE 当主力 | 华硕创 14 的 128 GB，35999 元 |
| 70B 够用，少花一点 | 联想 YOGA Pro 15 的 64 GB，国补后约 28499 元 |
| 试试 32B | 18999 元的创 14（32 GB）。它不是 70B / 120B 机器 |
| 只做推理，不需要 Windows 和游戏 | 现货 DGX Spark 小主机。系统是 Linux 开发机 |
| 游戏、14B 以内模型、沿用现有 x64 环境 | 保留桌面 5060 Ti 16 GB |

128 GB 上应优先 MoE，而不是把 70B 稠密模型当成对话主力。

## 10. 小结

| 要点 | 结论 |
| --- | --- |
| 换什么 | 统一内存换可装入规模，低功耗换笔记本形态 |
| 不换什么 | 出字速度仍由约 300 GB/s 带宽决定 |
| 32 GB 档 | 换不来比桌面 5060 Ti 16 GB 更强的游戏或小模型 |
| 70B / 120B | 至少 64 GB；120B MoE 直接上 128 GB |
