# DSH 插件安装使用入门

> **DeepSeek Harness**（命令名 `dsh`）把模型、工具和界面都做成插件。官方界面默认只列出少量官方插件。要逛社区插件，先装市场插件，再用同一条命令把需要的包装进正在用的 profile。

## 1. 先分清 profile

插件装进 `$DSH_HOME/profiles/<名字>`，不是装进某一个窗口。Windows 上通常是 `%USERPROFILE%\.dsh\profiles\`。

| profile | 谁在用 |
| --- | --- |
| `web` | `dsh web` 打开的网页，默认 `http://127.0.0.1:3080` |
| `desktop` | 官方桌面端。和 `web` 不共用已装插件 |

`--profile` 必须和当前客户端一致。装到 `web` 再打开桌面端，桌面端里看不到。下面命令以 `web` 为例，桌面端把 `web` 换成 `desktop`。

---

## 2. 安装 dsh 和 pnpm

Git Bash 里 `dsh: command not found`，是全局还没有这个命令。Node 24 可用时：

```bash
npm install -g @deepseek-ai/dsh
# 把 npm 全局 bin 加入 PATH（Windows Git Bash 常见在 ~/AppData/Roaming/npm）
export PATH="$PATH:$HOME/AppData/Roaming/npm"
dsh --version
```

Windows 上有时只有 `dsh.cmd`。`dsh` 仍找不到就改用 `dsh.cmd`。不想全局安装时，把命令里的 `dsh` 换成 `npx @deepseek-ai/dsh`。

`dsh plugin` 内部调用 `pnpm`。没有 `pnpm` 时，Windows 报「不是内部或外部命令」。用 Node 自带的 Corepack 装上，并新开一个终端：

```bash
corepack enable
corepack prepare pnpm@11.7.0 --activate
pnpm -v
```

嫌敲命令麻烦时，也可以把包名发给已经在跑的 DSH，让它自己搜、自己装。前提是 `dsh` 和 `pnpm` 已经在 PATH 里。

## 3. 先装市场，再装具体插件

`dsh plugin --profile <名字> add <包>` 会在该 profile 里执行 `pnpm add`，并把带 `dsh.bundle` 的包写进 `dsh.profile.bundles`。装完后重启这个 profile。

官方默认列表很短，第一步通常是市场：

```bash
dsh plugin --profile web add dshmarket
```

装完在设置里打开，目录按卡片浏览，并标了引擎兼容性。大市场容易眼花时，再装精选索引。收录要求公开源码、有可安装的 npm 包、许可证明确，默认按近期增速而不是历史总星标排序：

```bash
dsh plugin --profile web add "git+https://github.com/polang233/dsh-plugin-index.git#main&path:/packages/dsh-open-market"
```

不想装这个插件时，索引源可以直接加 `https://dshopen.org/index.json`。

pnpm 11 打印 `Lockfile passes supply-chain policies` 表示检查已经通过，不是还要再点一次确认。后面若是 `added 0`，说明这次没有装进新包，打开该 profile 的 `package.json` 看依赖是不是你要的地址。

## 4. 从 GitHub 安装时走 HTTPS

上面这条 git 地址，pnpm 仍可能去执行 `git ls-remote git+ssh://git@github.com/...`。本机没有 `~/.ssh`、也没有 GitHub 私钥时，会报 `Host key verification failed`。这是还没信任 `github.com` 的主机密钥，不是网络连不上。

公开仓库改走 HTTPS：

```bash
mkdir -p ~/.ssh
ssh-keyscan -t ed25519 github.com >> ~/.ssh/known_hosts
git config --global url."https://github.com/".insteadOf "git+ssh://git@github.com/"
git config --global url."https://github.com/".insteadOf "ssh://git@github.com/"
```

Git 第一次弹出 github.com 指纹确认时，指纹与 GitHub 公布的 ED25519 密钥一致再点 OK。这个框只记住服务器，不代表本机存了别人的账号密钥。

有的仓库要在安装时跑 `prepare`。pnpm 会拦住，直到你把它打印出的包名写进该 profile 的 `pnpm-workspace.yaml` 的 `allowBuilds`，再执行一次安装。这和主机密钥不是同一步。

同名 npm 包会装错。例如 cockpit 不要直接 `add dsh-cockpit`，按仓库 [v1.2.0 发布页](https://github.com/zoe1nan/dsh-cockpit/releases/tag/v1.2.0) 下载 `dsh-cockpit-1.2.0.tgz`，再：

```bash
dsh plugin --profile web add /path/to/dsh-cockpit-1.2.0.tgz
```

## 5. 装好之后怎么用

重启对应的 profile。插件出现在「设置 → 插件」。需要密钥的，在插件配置里填，写入 DSH 自己的凭据存储，不要写进仓库。

使用方式由插件自己规定：

- 装上就进工具列表。对话里直接说要做什么。知乎检索 `dsh-zhihu-search` 提供站内搜索、全网索引和知乎直答，密钥在知乎开放平台申请，官方接口按账号有日限额。
- 用一条入口消息进入专用界面。`dsh-tongflow` 要求新建会话，第一条以 `@tongflow` 开头，这一轮才变成画布工作室；其它会话仍是普通对话。本机需要 Python 3.10 或更高、`git`，做视频预览还要 `ffmpeg`。
- 斜杠命令。`dsh-tower` 用 `/tower` 把当前会话切成控制塔，工人改代码在独立 git worktree 里，通过检查后才合并。

`web` 和 `desktop` 各装一次，才会在两边都出现。

## 6. 社区里常提到的插件

版本和星标是盘点写作时的数字，会变。安装前看仓库自己的 `dsh` 版本要求。

**基础**

| 插件 | 命令 | 做什么 |
| --- | --- | --- |
| dshmarket | `dsh plugin --profile web add dshmarket` | 在设置里浏览、搜索、安装社区插件 |
| dsh-open-market | 见上文 git 地址 | 精选索引，按近期增速排 |
| dsh-cost-meter | `dsh plugin --profile web add dsh-cost-meter` | 统计每个会话和每天的模型费用 |
| dsh-plugin-health | `dsh plugin --profile web add dsh-plugin-health` | 升级 dsh 前检查已装插件能否加载 |

**多个 agent**

| 插件 | 怎么用 |
| --- | --- |
| dsh-tower | `/tower`。工人在独立 worktree 里改代码，审查通过才合并 |
| dsh-cockpit | 用上面的 tgz 安装。多个 agent 的进度、卡点和待审批放在一块看板，可在手机上看 |
| agency-agents | 一包很多带提示词的角色，按场景选用 |
| dsh-roundtable-harness | 让本机已配置的模型按人设讨论并打分，可导出 docx |

**搜索和资料**

官方搜索 API 按成功请求计费，盘点里写的是每 1000 次 5 元。不想付这笔钱时，社区用免费引擎做兜底。

| 插件 | 命令 | 做什么 |
| --- | --- | --- |
| dsh-free-search | `dsh plugin --profile web add dsh-free-search` | 聚合 Bing、DuckDuckGo 等，可失败切换，不必填 Key |
| dsh-zhihu-search | `dsh plugin --profile web add dsh-zhihu-search` | 知乎站内、全网和直答。需要开放平台 Access Secret |
| dsh-pdf-mineru | `dsh plugin --profile web add dsh-pdf-mineru` | 用 MinerU 解析复杂表格、公式和扫描 PDF |
| dsh-ai-library | `dsh plugin --profile web add dsh-ai-library` | 本地资料库面板，多种预览，并接论文检索 |

**画布、生图和长文**

| 插件 | 命令 |
| --- | --- |
| dsh-tongflow | `dsh plugin --profile web add dsh-tongflow` |
| dsh-image-gen | `dsh plugin --profile web add dsh-image-gen` |
| dsh-brewreel | `dsh plugin --profile web add dsh-brewreel` |
| Blender | `dsh plugin --profile web add @deepblend/dsh-blender-bundle` |
| 长篇 | `dsh plugin --profile web add dsh-openwrite` |
| 网文章节 | `dsh plugin --profile web add dsh-cuigengji-plugin`，以及 `dsh-novel-writer` |

前端方面，盘点还提到本地视频工作室 `eac-design-world`，以及先出几个视觉方向、定稿后再写页面并自己截图验货的 `github:oil-oil/dsh-oil-ui`。

**记忆和拦截**

这一组标成可选：解决的是长会话和误删，但容易和官方正在做的上下文功能重叠，安全检查也会多花 token。

| 插件 | 命令 | 做什么 |
| --- | --- | --- |
| ReMe | `dsh plugin --profile web add @agentscope-ai/reme-dsh-plugin` | 对话沉淀成本地 Markdown，跨会话检索 |
| memsearch | `dsh plugin --profile web add @zilliz/memsearch-dsh` | 多个编程 agent 共享一套记忆 |
| billion-context | `dsh plugin --profile web add billion-context` | 折叠历史上下文，需要时再召回 |
| cc-safety-net | `dsh plugin --profile web add cc-safety-net` | 执行前拦住破坏性命令和读密钥 |

## 7. 安装时看什么

第三方插件在你的用户权限下运行，能接触文件、凭据和网络。社区目录不是官方审核名单。

装之前看三件事：包名是不是盘点里写的那一个，有没有同名包；`package.json` 里的 `engines.dsh` 是否盖住你正在用的 dsh 版本；仓库是不是你打算给它文件和网络权限的来源。升级 dsh 之前，用 `dsh-plugin-health` 看已装插件还能不能加载。

## 8. 小结

| 要点 | 结论 |
| --- | --- |
| profile | `web` 与 `desktop` 不共用插件，`--profile` 必须和客户端一致 |
| 安装顺序 | 先有 `dsh` 和 `pnpm`，再装市场，再装具体包 |
| GitHub | 公开仓走 HTTPS；同名 npm 包宁可下 tgz |
| 安全 | 社区目录未审核；核对包名、引擎版本和仓库来源 |
