# 基于心理评估量表的精神障碍筛查系统技术方案

> 整理一类常见需求：**基于心理评估量表（如 MMPI）构建评分与筛查辅助能力**，并结合自评、他评、半结构式访谈及判别规则，形成可落地的技术方案与模块划分。文中开源仓库仅作实现参考。**系统输出仅为筛查与辅助参考，不能替代精神科医师诊断；量表版权与常模使用须合规授权。**

**参考与延伸阅读**：

- 在线测验示例：<https://mmpi-chn.github.io/MMPI-1-test.html>

## 一、目标与边界

典型建设目标可概括为两条能力链：

1. **心理评分**：按标准化量表完成作答、计分、常模对照与结果解释。  
2. **筛查判别辅助**：融合自评 / 他评 / 访谈等特征，对照公开诊断分类体系中的结构化条目，输出**风险等级与建议措施**（非正式诊断结论）。

| 应做 | 不宜宣称 |
|------|----------|
| 标准化量表作答与计分 | 「自动确诊某精神障碍」 |
| 多源结果汇总与规则提示 | 替代面诊与临床综合判断 |
| 报告、统计、权限与对接 | 未经授权复制商用量表全文 |

## 二、背景知识

### 2.1 MMPI 简介

**MMPI（Minnesota Multiphasic Personality Inventory，明尼苏达多项人格测验）** 是广泛使用的人格与精神病理学评估工具之一。实现层面需把握：

| 要点 | 说明 |
|------|------|
| 题量 | 常见完整版与简化版（题量以授权版本为准） |
| 临床量表（示例） | Hs、D、Hy、Pd、Mf、Pa、Pt、Sc、Ma、Si 等 |
| 效度量表（示例） | L、F、K、疑问分等 |
| 计分 | 原始分 → 常模转换（如 T 分）→ 剖面图与解释规则 |
| 标准化 | 题目、计分键、常模与解释须按正式手册执行 |

### 2.2 诊断分类参照（数据化，非自动下诊断）

工程上常把下列体系**结构化为规则/知识库**，供匹配与提示：

| 标准 | 发布方 | 备注 |
|------|--------|------|
| DSM-5 | 美国精神医学学会 | 国际常用 |
| ICD-11 | 世界卫生组织 | 全球分类标准 |
| CCMD-3 | 中国精神障碍分类与诊断标准 | 国内临床语境常需对照 |

### 2.3 开发要点

- **量表标准化实现**：版本、计分键、常模一致，结果才可解释。  
- **计分准确性**：T 分/常模对照需可单测、可审计。  
- **结果与标准的映射**：只做筛查提示，规则需临床专家审核。  
- **多源融合**：自评、他评、访谈权重与冲突处理需可配置。  
- **专业报告**：含量表分数、剖面图、风险提示与免责声明。

## 四、能力架构总览

```text
受试者 / 知情者 / 评估员
        │
        ├─ 自评量表（标准化题库 + 断点续答）
        ├─ 他评量表（权限与一致性）
        └─ 半结构式访谈（模板 + 结构化记录）
                │
                ▼
        计分引擎（原始分 / T 分 / 常模 / 效度）
                │
                ▼
        判别规则引擎（多源融合 + 诊断条目匹配 + 风险等级）
                │
                ├─ 个人 / 群体评估报告（图表、导出）
                ├─ 统计报表
                └─ 可选：对接业务系统 / SSO
```

**推荐原则**：计分与阈值判别走**确定性规则/代码**；大模型若使用，仅做报告润色或访谈摘要，**不直接改量表分数、不替代规则引擎**。

## 五、核心模块技术要点

### 5.1 量表库与作答

| 子模块 | 要点 |
|--------|------|
| 题库与元数据 | 版本、适用人群、维度、选项定义；支持版本切换 |
| 作答体验 | 分页、进度、必答与跳转、防误触 |
| 数据可靠性 | 断点续答、提交校验、防丢答 |

### 5.2 计分引擎（核心）

| 子模块 | 要点 |
|--------|------|
| 计分规则 | 原始分、校正、临床/效度量表分 |
| 常模对照 | 分人群常模；百分位 / T 分等 |
| 解释配置 | 风险提示、剖面图解读规则（由专家审核，开发侧做配置与执行） |

### 5.3 自评 / 他评 / 访谈

| 方式 | 技术关注点 |
|------|------------|
| 自评 | 多题型、结果存储与基础报告 |
| 他评 | 知情者身份与权限、多人结果汇总与一致性 |
| 半结构式访谈 | 提纲模板、文本/音视频记录、结构化症状录入、检索 |

访谈可与自评/他评结果**联动触发**（见下一章）。

### 5.4 判别逻辑（核心）

| 子模块 | 要点 |
|--------|------|
| 标准库 | 将 ICD-11 / CCMD-3 等条目结构化（症状、时程、严重度） |
| 量表—标准映射 | 量表剖面与障碍类别提示的关联表（专家维护） |
| 规则引擎 | 多条件组合：分数阈值、症状组合、访谈条目；输出高/中/低风险等 |
| 多源融合 | 自评/他评/访谈权重可配置；冲突时标记「需人工复核」 |
| 风险行为提示 | 如自伤、攻击等线索条目（按机构规范配置，需强合规） |

自动判别结果应表述为 **筛查建议 / 风险提示**，并强制人工复核入口。

## 六、流程、触发与集成

### 6.1 分人群检测流程

不同身份（如体检人群、专项筛查人群）可配置**不同流程模板**：节点顺序、是否强制访谈、报告模板等。需流程引擎支持条件分支与状态跟踪。

### 6.2 访谈触发

| 能力 | 说明 |
|------|------|
| 条件配置 | 基于自评/他评分量表阈值、效度异常等 |
| 任务生成 | 触发后生成访谈任务并通知评估员 |
| 可配置性 | 条件可改，避免写死单一业务线 |

### 6.3 系统对接（可选）

| 对接类型 | 典型内容 |
|----------|----------|
| 业务/体检系统 | 拉取人员主数据；回写评估摘要或报告链接 |
| SSO | OAuth2 / SAML 等；跨系统免登跳转与会话 |

接口需日志、重试与幂等；评估数据属敏感个人信息，传输与存储需加密与最小权限。

## 七、报告与运维能力

| 能力 | 要点 |
|------|------|
| 个人报告 | 分数表、剖面图、标准对照摘要、风险与建议、免责声明 |
| 群体报告 | 批次汇总、阳性率等（按权限脱敏） |
| 导出 | Word / PDF / 表格；异步任务与进度 |
| 统计报表 | 可配置维度与指标 |
| 人员与用户 | 受试者档案、批量导入导出；角色（管理员/评估员/受访者）与权限 |
| 离线包 | 约定 Excel/CSV/JSON 格式，校验后批量入库 |

## 八、实施注意与风险

| 风险 | 对策 |
|------|------|
| 量表与常模版权 | 采购正版授权；开源 Demo 仅学流程，勿直接商用题库 |
| 把筛查当诊断 | 产品文案、报告页、接口字段统一「辅助/筛查」表述 |
| 计分偏差 | 黄金用例单测；与专家手算样本对拍 |
| 敏感数据 | 脱敏导出、审计日志、访问控制；音视频访谈尤需规范 |
| LLM 幻觉 | 禁止 LLM 重算分数；仅润色已由规则生成的结论 |

相对投入上，**量表库 + 计分 + 判别规则 + 专业报告** 通常是工期与风险的主要部分；账号、导入导出等为常规能力。

---

## 九、小结

| 要点 | 结论 |
|------|------|
| 能力链 | 标准化作答计分 → 多源融合 → 规则化筛查提示 → 报告与对接 |
| 技术关键 | 计分引擎与规则引擎必须确定性、可审计 |
| 开源价值 | 参考答题与常模展示实现；不能替代授权与临床规范 |
| 合规底线 | 非诊断结论；量表版权与隐私合规优先 |
